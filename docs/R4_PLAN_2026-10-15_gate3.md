## TOUCH POINT 1 — the verdict block, `:2180`–`:2203`

**Now** (D6): compute `looser`, log either way, then **always** `sl = ddSL;`.

**After** (D20): the same comparison **decides** instead of only narrating.

```
         // D20 (E9-R3, Jeff 2026-10-15): *** THE BOUNDARY TAKES THE SL ONLY WHEN TIGHTER. ***
         // SUPERSEDES D6. The comparison below used to only NARRATE the overwrite; now it
         // DECIDES it.
         if(sl > 0.0 && MathAbs(sl - ddSL) > tolSLOwn)
           {
            bool looser = (dirSLOwn > 0) ? (ddSL < sl) : (ddSL > sl);
            if(looser)
              {
               // A-1/A-2/A-5: the stop in charge is TIGHTER. KEEP IT. The cap is not
               // under-enforced - a tighter stop makes it UNREACHABLE.
               if(!AlreadyLogged("ddkeep:" + DoubleToString(sl, _Digits) + ":" + DoubleToString(ddSL, _Digits)))
                  Log(LOG_INFO, StringFormat("%s SL %s is TIGHTER than the drawdown boundary %s - KEPT (E9-R3 D20: the cap is a CEILING on risk, not a floor). Max loss at this stop is %s%.2f %s against the $%.2f cap. The boundary re-asserts as soon as it becomes the tighter of the two.",
                                             SLOwnerName(), DoubleToString(sl, _Digits),
                                             DoubleToString(ddSL, _Digits),
                                             ...signed money at sl...,
                                             AccountInfoString(ACCOUNT_CURRENCY), EffectiveDDCap()));
               // A-6: ddSL is NOT assigned. `sl` stands.
              }
            else
              {
               // A-3/A-4 UNCHANGED: the boundary is genuinely tighter and still wins.
               if(!AlreadyLogged("ddtighten:" + DoubleToString(ddSL, _Digits)))
                  Log(LOG_INFO, StringFormat("DD boundary %s replaces the %s SL %s (tighter; E9-R1 D6/D11). Cap $%.2f, %d level(s) afforded.", ...unchanged...));
               sl = ddSL;
              }
           }
         else
            sl = ddSL;   // A-7: equal within tolerance - assign for exactness, no log
```

- **The loosening WARN is DELETED, not reworded** (A-6). It said *"Your stop moves AWAY from
  price"* — under D20 that no longer happens for a kept stop, and leaving a WARN that describes
  an action the code no longer takes would be a false claim in the log. Same D18 precedent set in
  b53: an unreachable branch gets replaced by a line stating what is true.
- **`sl = ddSL;` moves INSIDE the branches.** This is the whole fix. The `else` arm at the end
  preserves exact assignment in the equal case so no float residue survives.
- The new INFO states the **money at the kept stop against the cap**, because "tighter" is a
  price claim and the thing a trader needs is the risk claim. The 22:34 case would read
  *"+0.19 against the $52.13 cap"* — which makes the old behaviour self-evidently wrong.

## TOUCH POINT 2 — `SLOwnerName()`, a new 6-line helper placed immediately above `EnforceExits`

D6's log named only two owners: `g_state.manualSL > 0 ? "manual" : "computed"`. **That is why the
22:34 line called the BE floor "computed"** and why the defect read as a manual-SL problem for
one run longer than it should have. D20 must name four.

```
// D20: name the stop ACTUALLY in charge. D6's two-way label called the BE floor "computed",
// which is how the 22:34 BE case was first misread.
string SLOwnerName()
  {
   if(g_state.trailingActive)      return "trail ratchet";
   if(g_state.manualSL > 0.0)      return "manual";
   if(g_state.beApplied)           return "BE floor";
   return "computed";
  }
```

**Order is load-bearing and matches the real precedence** in `ApplyProtectiveEngines`: the trail
ratchet zeroes the TP and owns the SL outright; a manual stop substitutes before the engines run;
the BE floor is applied on top via `ProtectiveSL`. Declared **above** `EnforceExits` — MQL5
resolves functions forward, but b52's `DD_RESTEP_PCT` lesson was about macros, and placing it
adjacent to its only caller costs nothing.

## RISK, STATED PLAINLY

The change is ~20 lines in one block plus a 6-line helper. The sharp edge is **not** the
comparison — it is that D20 **removes a safety net that was masking the behaviour of another
gate**. While D6 overwrote everything, a bug in D16-C could never widen the cap, because the
boundary reasserted itself a millisecond later. After D20, **D16-C is the sole barrier**.
That is why matrix **D-1** is the row that decides this build, and why A-2 was deliberately proven
on b53 *before* the net came off. **The thing most likely to be wrong is not in this diff — it is
whether D16-C holds under inputs b53 did not test** (SELL direction, multi-level, post-restart).
