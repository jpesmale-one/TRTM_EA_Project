## THE CONSTRAINT THAT SHAPES THE WHOLE FIX

**The helper CANNOT call `ApplyProtectiveEngines`.** Scanned `:1605`–`:1700`: it sets
`g_state.beApplied`, sets `g_state.trailingActive`, zeroes `g_state.manualSL`, calls `StateSave`
**twice**, writes `g_trailCand` / `g_lastTrailBar`, and logs the BE-TRIGGERED and
TRAILING-ACTIVATED transitions. Calling it from a 500 ms panel refresh would **arm BE from the
dashboard** and save state three times a second.

So the helper must **replicate the merge while skipping every transition**. That is the one real
piece of design in this build, and it is why A-6 (purity) is the row that matters most.

| Engine does | Helper must do |
|---|---|
| `if(!beApplied && trigger met)` → **set the flag, log, save** | **nothing** — never arms anything |
| `if(beApplied) sl = ProtectiveSL(sl, BEStopPrice(), dir)` | **the same merge**, read-only |
| `if(!trailingActive && activation met)` → **arm, release, save** | **nothing** |
| `if(trailingActive)` → ratchet + floor, writes `g_trailCand` | read the **live broker SL**, as `:5108` already does |

**The helper reports the stop as it stands THIS INSTANT.** It never predicts a transition that has
not happened — a projection that armed BE early would be worse than the defect it replaces.

## TOUCH POINT 1 — `ProjectedStopPrice()`, new pure helper, placed directly above `LogStructure`

```
// b56 (E9-R3-B): THE ONE DERIVATION OF "WHAT STOP IS ACTUALLY IN CHARGE".
// Mirrors EnforceExits' ladder for REPORTING only. MUST NOT call
// ApplyProtectiveEngines - that function ARMS BE, ARMS TRAILING, zeroes manualSL,
// logs transitions and calls StateSave TWICE. From a 500ms panel refresh it would
// arm BE from the dashboard.
double ProjectedStopPrice(const double computedSL)
  {
   if(g_state.levelCount == 0 || g_state.direction == 0) return 0.0;
   int dir = g_state.direction;
   double sl = computedSL;

   if(g_state.manualSL > 0.0) sl = g_state.manualSL;          // b24

   if(g_state.trailingActive)                                  // Stage 6: ratchet owns it
     {
      double live = 0.0;
      for(int i = 0; i < g_state.levelCount; i++)
         if(PositionSelectByTicket(g_state.tickets[i]))
            live = ProtectiveSL(live, PositionGetDouble(POSITION_SL), dir);
      return (live > 0.0) ? live : sl;                         // boundary never overrides the ratchet
     }

   if(g_state.beApplied)                                       // *** THE GAP: never merged in display ***
      sl = ProtectiveSL(sl, BEStopPrice(), dir);

   if(InpEnableDDClose)                                        // D20: tighter-of-two, NOT unconditional
     {
      int lv = 0; bool now = false; double tr = 0.0;
      double b = DDBoundaryPrice(lv, now, tr);
      if(b > 0.0)
        {
         if(sl <= 0.0) sl = b;
         else { bool tighter = (dir > 0) ? (b > sl) : (b < sl); if(tighter) sl = b; }
        }
     }
   return sl;
  }
```

- **The `sl <= 0.0` case matters** and is not an afterthought: with `InpStopLossPts = 0`, no manual
  stop and no BE, the boundary is the ONLY stop — Jeff's standing configuration. It must still be
  priced, which is the A-2 regression of b48/D9's original fix.
- **Trailing returns early**, matching `EnforceExits`, where the boundary block is skipped for a
  trailing sequence (`LogStructure` `:2740` and `PanelRefresh` `:5114` both already gate on
  `!trailingActive`). Same behaviour, now stated once.

## RISK, STATED PLAINLY

The sharp edge is **A-6 purity**, and it is not theoretical: the obvious implementation — "just
call `ApplyProtectiveEngines`" — would arm BE from a 500 ms dashboard refresh and write the state
file three times a second. The helper is deliberately a **replication**, which means it can drift
from the engine in a future build. That is the cost of A-7 keeping the engine's ladder separate,
and B-2 is the row that catches the drift: *the projection must equal the SL actually applied.*
