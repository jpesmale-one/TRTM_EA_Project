## THE RULE THIS BUILD ENCODES

  DELETION      MT5 -> file.  A ticket leaves the record ONLY on affirmative evidence.
  RECONCILIATION file -> MT5.  The file proposes; MT5 confirms by ticket.
An ABSENCE can never delete anything.

## FACTS ESTABLISHED AT SCOPING (verified in code, not assumed)

F1. ClosingDealReason has EXACTLY ONE CALLER (962). The helper's contract can change with no
    risk of a second consumer drifting out of step.
F2. It already distinguishes three cases internally and COLLAPSES them all to 0:
      927  HistorySelectByPosition FAILED              -> 0   NO EVIDENCE
      941  default: a closing deal EXISTS, other reason -> 0   GENUINELY CLOSED (manual)
      944  loop ended, no DEAL_ENTRY_OUT found         -> 0   NO EVIDENCE
    Two of the three are UNKNOWN; one is a real close. That collapse IS the defect.
F3. WasEAClosed (956) SHORT-CIRCUITS BEFORE the history test, and MarkEAClosed is called only
    after a CONFIRMED successful PositionClose (1552). So a ticket the EA itself closed can
    never be misread as UNKNOWN. One whole class of false-UNKNOWN is already excluded by
    existing code - no new work needed for it.
F4. g_eaClosed is in-memory only and is cleared on flat (994). AT RECONCILE IT IS ALWAYS
    EMPTY, so reconcile cannot use WasEAClosed and must rely on history alone. That is
    CORRECT: a position the EA closed before shutdown has a closing deal in history.
F5. 20 call sites already guard with `if(!PositionSelectByTicket(...)) continue;`, so a
    KEPT-but-unselectable record is inert to ComputeTargets, FormBasketGroup, EnforceExits
    and the projections. This is what makes "keep the record" a safe instruction (matrix D-5).
