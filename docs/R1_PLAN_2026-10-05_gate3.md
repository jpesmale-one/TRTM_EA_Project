## THE CENTRAL FINDING THAT SHAPES THIS PLAN

**The EA already has a structural-change concept, and it already fires at exactly the events D4
defines as re-derive triggers.** b24's `ReleaseManualTP(trigger)` is called at:

| line | event | D4 trigger? |
|---|---|---|
| [2777](../src/TRTM.mq5#L2777) | `TrackLevel` — a level is REGISTERED | **yes** (level opens) |
| [1028](../src/TRTM.mq5#L1028) | liveness prune — a leg CLOSED, behind the `changed` flag | **yes** (leg closes) |
| [2906](../src/TRTM.mq5#L2906) | death-window — closed while EA was offline | **yes** (restart, E-1) |
| [1472](../src/TRTM.mq5#L1472) | trailing armed | no — not a structural lot/level change |

So the re-derive hook **rides the existing structural path** instead of inventing a parallel one.
This is what makes rows **D-2** (no per-tick re-derive) and **D-3** (no per-bar re-derive) true
*by construction* rather than by a guard that could be forgotten.

### THE ONE GAP — and it is row D-6, the subtlest trigger

**A Tier 3 partial close does NOT pass through either chokepoint.** At
[1645](../src/TRTM.mq5#L1645) `PositionClosePartial` succeeds, the ticket **survives**,
`levelCount` is **unchanged**, and **no `ReleaseManualTP` fires**. Riding the b24 hook alone
would silently miss D-6: the boundary would keep using **pre-slice lots**, sit **too far from
price**, and **under-enforce the cap** — a loss cap quietly wider than the declared 2%.

=> Tier 3 gets its **own explicit hook** (touch point 7). This is the single most important line
in the plan, and it is exactly the class of defect the matrix exists to catch.

## TOUCH POINTS

### 1. `EffectiveDDCap()` — new function, near `SequenceFloatingPnL` (~3753)
Returns the effective cap in **account currency**, or 0.0 when not armed.
- `pctCap = AccountInfoDouble(ACCOUNT_BALANCE) * InpMaxDDPercent / 100.0` when pct > 0
- `usdCap = InpMaxDDUSD` when usd > 0
- **MIN of the positive limits** (D1). Both off → return 0.0 = NOT ARMED.
Covers **A-2 … A-5**. Pure function, no side effects, safe to call from the dashboard.

### 2. `ValidateInputs()` — extend (~4767)
- `InpEnableDDClose && pct <= 0 && usd <= 0` → **LOG_ERROR**, refuse to arm, dashboard warn (**A-6**).
- `pct < 0 || usd < 0` → LOG_ERROR, refuse to arm, name the value (**A-7**).
- **Does NOT set `g_configBlocked`.** b17's config-block is a *full trading freeze*; a
  misconfigured DD cap must not freeze a live sequence that other rules still protect. It refuses
  to **arm**, loudly — b19-consistent, and consistent with D1's own both-off rationale.

### 3. `ProjectedLevelPrice()` + `DDBoundaryPrice()` — new, near `ComputeRecoveryTrigger` (~2260)
**THE B-3 ANTI-DUPLICATION REQUIREMENT.** First extract the interval step from
`ComputeRecoveryTrigger` ([2256](../src/TRTM.mq5#L2256)) into one shared helper:
```
double NextLadderPrice(const int dir, const double fromPrice)
  { return (dir < 0) ? fromPrice + InpRecoveryIntervalPts * _Point
                     : fromPrice - InpRecoveryIntervalPts * _Point; }
```
`ComputeRecoveryTrigger` is then **rewritten to call it**, so engine and projection cannot drift —
there is only ever ONE copy of the interval maths (**B-3**, the biggest build risk in R1).

`DDBoundaryPrice()` then:
1. anchors on the **worst SURVIVING entry** (the engine's own anchor, D4/**D-4**)
2. computes `realised` banked this sequence; `remaining = cap - |realised|`
3. `remaining <= 0` → return market-adjacent price = close now (**D-9**, no divide-by-zero)
4. walks levels with `NextLadderPrice`, lots from the **sealed `ComputeLevelLot(levelN)`**
   (**B-2**, **B-7** clamping inherited)
5. accumulates DD using the existing tick-value idiom
   (`SYMBOL_TRADE_TICK_VALUE` / `TICK_SIZE`, `tickSz<=0 → _Point` fallback, as at
   [2176](../src/TRTM.mq5#L2176)) — **no new money maths**
6. stops at the first level where cumulative DD >= remaining → that level's price
7. terminator: `InpMaxRecoveryTrades` when > 0 (**B-4**), else budget, with a **hard 200-level
   bound** → refuse to arm + log if hit (**B-5**)
8. offset **10 points** on the safe side, direction-correct for BUY/SELL (**B-10**)
9. must never return a price on the wrong side of entry (**B-6**)

### 4. `DD_OFFSET_PTS` — new `#define`, value 10
A constant, not an input (resolved at seal). 10 points = 1 pip on all four symbols.

### 5. `ApplyDDBoundary()` — new, near `EnforceExits` (~1794)
Writes the boundary SL to **every** live leg (**C-1**):
- **Idempotence first** — skip `PositionModify` when the SL already equals the boundary within
  tick tolerance (**C-8**, no log spam).
- `TradeTargetLive(ticket)` gate before every modify — b42/E9-Q3, never read `Result*()` on a
  no-send path (**C-7**).
- Clamp to `BrokerStopsLevelPts()` ([3533](../src/TRTM.mq5#L3533)) per b27, log the clamp (**C-6**).
- **C-5 WARN:** when the existing SL is **TIGHTER** than the boundary and gets loosened, log
  LOG_WARN naming **both** prices and the cap. Jeff accepted this under D6; it must never be silent.
- Skips tickets `TradeTargetLive` rejects (**E-4**, the b44 UNKNOWN class).

### 6. `MaybeRederiveDDBoundary(const string trigger)` — new orchestrator
`if(!InpEnableDDClose) return;` → compute cap → compute boundary → apply → log once with
**cap, realised, remaining, boundary price, levels afforded** (**F-3**, observability rule).
Called from the four structural sites, **never from OnTick directly** (**D-2**, **D-7**, **F-7**).

### 7. Hook the structural sites — the behavioural core
| site | line | row |
|---|---|---|
| `TrackLevel`, after `ReleaseManualTP` | 2777 | **D-1** |
| liveness prune, inside `if(changed)` + `levelCount > 0` | ~1028 | **D-4**, **D-5**, **D-7** |
| **`FireTier3Slice` after a SUCCESSFUL partial** | **~1656** | **D-6 — the gap above** |
| `OnInit` after state load / death-window | ~2906, ~5067 | **E-1**, **E-2**, **E-3** |

Input-edit re-derive (**A-8**, **D-8**) comes free: changing an input reloads the EA, so OnInit
re-derives. Recorded explicitly so it is not mistaken for an untested path.

### 8. `EnforceExits()` — DD boundary takes SL ownership (~1794)
When armed, the DD boundary is the SL: `InpStopLossPts` **concedes** (D2, **C-2**, **C-3**), and
it **overwrites a manual SL** (D6, **C-4**, **C-5**). Scoped strictly to `InpEnableDDClose == true`
— with it false, b24's asymmetry is byte-for-byte unchanged (**F-6**).

### 9. `PanelRefresh()` / dashboard (~4152)
One DD row while armed: **boundary price + levels afforded** (**F-1**). Absent when disabled
(**F-2**), matching the existing DD-Reduction row idiom.

### 10. `OnTick` — cleanup on flat (~5156)
Clear cached boundary state when `levelCount` reaches 0, so nothing leaks into the next sequence
(**D-10**).

### 11. `README.md`
Replace the E9-R1 "you did not have a loss cap" warning with shipped behaviour; beginner-audience
section (**F-8**).

### 12. `STATE.md`
b45 header, hash, lines; matrix disposition.
