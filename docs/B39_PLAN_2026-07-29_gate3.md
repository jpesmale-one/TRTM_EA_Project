## 0. SHAPE OF THE CHANGE

b39 stops assuming a fill is instantaneous. Registration becomes a per-tick WATCHER that
adopts any of our own tagged, untracked positions in BOTH states; the order book is read
with an ORDER_TYPE split so in-flight market orders are no longer mistaken for pendings;
and level 0 is abolished as an assignable level.

Nine touch points, all additive or filter-narrowing. NO new input, NO new persisted field,
NO state-schema change (R-3). No money-path function is opened (R-2): ComputeWeightedVWAP,
ComputeSlicedAnchorVWAP, ComputeTargets, FormBasketGroup, FireGroupClose, the tier gates
and the slice sizing are NOT in this plan.

Estimated delta: +95 to +115 lines, 4674 -> ~4780.

## 1. TOUCH POINTS

### TP-1  NEW HELPER: IsAdoptableOurPosition()          [E9-P1, E9-P2, W-1, L-2, L-3]
Insert immediately AFTER ParseLevelFromComment (ends 2469), BEFORE RebuildLiveMap (2471),
so it precedes every caller in this single-translation-unit file.

    // b39: THE one admission filter for "this position is ours and carries our tag".
    // Extracted from RebuildLiveMap (sealed since Stage 1) so the watcher, the
    // registration fast path and the flat scan cannot drift apart (E9-P1). Symbol is
    // compared NORMALIZED, matching RebuildLiveMap, not raw _Symbol (E9-P2).
    // Returns true and sets lvl on admission. lvl < 0 means the tag is unparseable -
    // the CALLER decides the level (never 0 - L-3).
    bool IsAdoptableOurPosition(const ulong ticket, int &lvl)

Body: PositionSelectByTicket -> false on failure; POSITION_MAGIC != g_magic -> false;
NormalizeSymbol(POSITION_SYMBOL) != g_symbolNorm -> false; lvl = ParseLevelFromComment(
POSITION_COMMENT); return true.

MAGIC IS THE HARD GATE (E9-N1, W-3): the magic test lives HERE and nowhere else, so no
caller can bypass it. A magic-0 mobile position fails at the second line and is invisible
to every b39 path. Adoption (TryAdopt / the untagged fallback) does not call this helper
and is untouched.

### TP-2  NEW: AdoptUntrackedLevel()                     [W-2, W-4, W-5, L-1, L-2, L-3]
Insert after TP-1. Single place where a ticket enters a LIVE g_state.

    bool AdoptUntrackedLevel(const ulong ticket, const int rawLvl, const string src)

Order of operations, and every one of these is a matrix row:
 1. Already tracked? scan g_state.tickets -> return false silently. (W-4, double-register)
 2. TRTM_MAX_LEVELS full -> LOG_ERROR, return false. (mirrors 1925)
 3. Level resolution:
      rawLvl >= 1                    -> use it.
      rawLvl <  1 (unparseable / 0)  -> lvl = maxTrackedLvl + 1, LOG_WARN naming the
                                        ticket and the raw comment. NEVER 0. (L-2, L-3)
    maxTrackedLvl is computed over g_state.levels exactly as ComputeRecoveryTrigger does
    at 2009-2011 - same idiom, so nextLvl and adoption agree.
 4. Duplicate-level check: if lvl already present in g_state.levels -> adopt ANYWAY,
    LOG_WARN naming BOTH tickets. (O2a / L-1 - the level is an address, not a key.)
 5. Direction check: position type vs g_state.direction; mismatch -> LOG_ERROR and REFUSE
    (return false). A counter-direction position under our magic is not a level of this
    sequence, and grafting it would corrupt the VWAP anchor. Mirrors RebuildLiveMap 2509.
 6. Append ticket + lvl, levelCount++.
 7. ReleaseManualTP(StringFormat("level add (L%d)", lvl)) - EXACTLY as RegisterNewRecovery
    does at 1933, so manual-TP ownership behaves identically. Manual SL untouched (M3-4).
 8. StateSave(g_state); Log(LOG_INFO, ticket + level + volume + src); LogStructure().
    (W-5: every adoption is journalled, which is what carries O2e's "not silent".)
 9. return true.

### TP-3  RegisterNewRecovery -> FAST PATH               [A-1, A-3, A-4, E9-O1/O2]
Rewrite 1911-1941 as a thin wrapper over TP-1/TP-2, preserving the exact-level semantics
it has today:

    bool RegisterNewRecovery(const int levelN)
      scan PositionsTotal(); for each ticket: IsAdoptableOurPosition(ticket, lvl);
      require lvl == levelN (unchanged from 1920); then AdoptUntrackedLevel(ticket,
      levelN, "fast path").
      MISS -> Log(LOG_INFO, "Recovery L%d: order accepted, fill pending - the watcher

The ERROR at 1939 becomes that INFO. This is the single line that stops Jeff's live log
from crying wolf on Vantage. On a SYNC broker the loop hits on the first pass and behaves
byte-identically to b38 (A-3, R-1).

A-4 is already structurally satisfied upstream and NEEDS NO CODE: the retcode gate at 2170
(and 3274) already rejects anything that is not DONE / DONE_PARTIAL / PLACED and returns
before registration, so a genuine FAILURE still ERRORs and never reaches the watcher.
Verification must SHOW this, not change it.

### TP-4  NEW: WatchUntrackedLevels()                    [W-1..W-6, A-1, A-2, A-5, F-2]
Insert after TP-2.

    void WatchUntrackedLevels()
      if(g_state.levelCount == 0 || g_state.direction == 0) return;   // live state only
      for i in PositionsTotal():
         ticket = PositionGetTicket(i); if 0 continue;
         if(!IsAdoptableOurPosition(ticket, lvl)) continue;
         AdoptUntrackedLevel(ticket, lvl, "watcher");

O(positions), no allocation, no ArrayResize (W-6). Inert and SILENT when everything is
tracked - step 1 of TP-2 returns false without logging, so a healthy sync-broker run gets
zero new journal lines (R-4).

A-5 IS CLOSED BY CONSEQUENCE, NOT BY NEW CODE: ComputeRecoveryTrigger derives BOTH nextLvl
(2009-2012) and worst (2017-2027) from g_state ALONE. Once the watcher registers the
in-flight L2, maxLvl becomes 2 and worst becomes L2's entry, so the trigger recomputes and
the every-M5-bar duplicate stacking stops. Verification must demonstrate this end to end.

### TP-10  RebuildLiveMap - NO LEVEL 0 AT STARTUP EITHER    [L-3, K-1, K-4] (Q-1 = a)

can never seize the anchor from a real L1. Documented here so verification does not read
it as a defect.
