## TOUCH POINTS — 9 sites

### TP1 — `ReleaseManualExits()`, NEW function (replaces `ReleaseManualTP`) · ~line 1227

**Why a rename, not an extra call:** D16 makes release symmetric. Leaving a TP-only function and
adding SL releases at four call sites would put the symmetry in the *callers*, where it can drift.
One function that releases both keeps the rule in one place.

```
void ReleaseManualExits(const string trigger)
  - releases manualTP exactly as b24 does (wording preserved)
  - ALSO releases manualSL, with its own WARN naming the price
  - F-2: if a successor stop is LOOSER than the released manual SL, state the
    money delta - a release must never widen risk silently
  - D16-E: if NO engine will claim the stop (InpStopLossPts <= 0 && !InpEnableDDClose
    && !beApplied && !trailingActive), announce the orphan and LEAVE THE STOP
```

Old name kept as a thin forwarder **only if** the diff gets noisy; otherwise all four call sites
are updated. Decide at build time, record which.

**Rows:** C-1, C-2, C-10, C-11, C-12, F-1, F-2

### TP4 — `AdoptPosition`, classify pre-existing exits · ~line 1050

**The R2-B root fix.** After `ResetExitEnforcement()` (which must still run — it clears the
*enforcement* baseline), read `POSITION_TP` / `POSITION_SL` from the adopted ticket and:

```
  - TP > 0  -> g_state.manualTP = TP ; g_lastAppliedTP = TP ; g_state.lastAppliedTP = TP
  - SL > 0  -> same, SL side, SUBJECT TO D16-C (see TP5)
  - MarkExitsApplied(ticket)   // the ticket is ARMED: it carries values the EA knows about
  - log the classification ON the adoption line, naming each owner
  - 0/0 -> nothing classified, b51 behaviour byte-identical (B-4)
```

**Ordering inside the function matters:** classification must happen **before** `StateSave` and
`LogStructure`, so the saved state and the logged projection both reflect ownership.

**B-3 is why TP and SL are handled independently:** the GBPJPY position carried a *trader* TP
(210.132) and an *EA-derived* SL (205.722) — two owners on one ticket. Classifying "the exits" as
a unit would mislabel one of them.

**Rows:** B-1, B-2, B-3, B-4, B-6, B-7, B-8

### TP5 — `DetectManualExitEdits`, the D16-C tighter-only gate · ~line 1790

In the `candSL` branch, **before** adoption: if the DD cap is armed and the candidate SL is
**looser** than the current boundary, **REFUSE** with a loud WARN naming both prices.

```
  if(InpEnableDDClose)
     ddB = DDBoundaryPrice(...)            // pure read, no writes
     looser = (dir > 0) ? (candSL < ddB) : (candSL > ddB)
     if(looser) -> REFUSE + WARN, do not adopt
```

**D16-D is honoured by construction here:** this gate sits in the *manual-edit* path only. The
EA's own re-derivation in `EnforceExits` never passes through `DetectManualExitEdits`, so a tier
close that loosens the boundary (D5) is unaffected. **That separation is the whole point** — same
direction of movement, two owners, two rules.

Every existing guard in this function is **retained verbatim**: post-BE floor refusal, conflict
detection, removal-never-adopted, the widening WARN.

**Rows:** C-3, C-4, C-5, D-1, D-2, D-3, D-4

### TP6 — the C-8 ordering fix · ~line 1716 / 2881

**This is the actual b51 failure mechanism and the subtlest item in the plan.**

Releases fire in `WatchUntrackedLevels` / `CheckSequenceLiveness`, which run **before**
`EnforceExits`. `DetectManualExitEdits` then sees the stale broker value, finds it differs from
both the new computed target and `lastApplied`, and **re-adopts it on the same tick**. Release and
re-adopt, in that order, within one tick.

**Reuse the existing precedent rather than inventing one.** `g_manualDetectSkipOnce` already
exists for exactly this problem — `ReconcileManualExits` sets it so the first post-restart pass
does not read its own classification as a trader edit. `ReleaseManualExits` sets the same flag.

```
  ReleaseManualExits() -> g_manualDetectSkipOnce = true
  DetectManualExitEdits() consumes it on the next pass (existing code, unchanged)
```

One flag, one consumer, already sealed and proven. **No new state, no new ordering assumption.**

**C-9 note:** `EvaluateBasketClose` runs *after* `EnforceExits`, so a tier release is not seen
until the next tick. The flag survives across ticks (it is consumed on the next *pass* of
`DetectManualExitEdits`, not the next tick), so the window is covered — **but C-9 must verify this
on evidence**, not on this reasoning.

**Rows:** C-8, C-9, B-5, B-8

### TP7 — the D15 deadband · ~line 1858, inside `if(ddSL > 0.0)`

```
#define DD_RESTEP_PCT  0.5    // percent of remaining budget (constant - Stage 1 dialog frozen)

  thresholdPts = (remaining * DD_RESTEP_PCT/100.0) / (mpp * liveLots)
  if a boundary SL is ALREADY on the positions and |ddSL - currentSL| <= thresholdPts * _Point
     -> HOLD: leave sl as the current value, do not rewrite
  else -> sl = ddSL   (b51 behaviour)
```

**A-9:** when no SL is on the position yet, the first boundary writes **unconditionally** — a
deadband against nothing must not suppress initial placement.

**A-7:** this gates the **write**, not the value. `DDBoundaryPrice` is untouched; D11's formula is
untouched; `AnnounceDDBoundary` still fires structurally (**A-8**).

`DDBoundaryPrice` already computes `remaining`, `mpp` and `liveLots` internally but returns only
the price. **Decision:** add two `const` out-params (`remainingOut`, `mppLotsOut`) rather than
recomputing in `EnforceExits` — recomputation would be a *second copy of the money maths*, which
is exactly the B-3 hazard D11 was built to avoid.

**Rows:** A-1, A-2, A-3, A-4, A-5, A-7, A-8, A-9, A-10, E-1
