## TOUCH POINT 1 — the baseline (D17 + D19), `:1880`–`:1885`

**Now:**
```
   // Baseline = what the EA itself last wanted: owned manual, else computed.
   double baseTP = (g_state.manualTP > 0.0) ? g_state.manualTP : compTP;
   double baseSL = (g_state.manualSL > 0.0) ? g_state.manualSL : compSL;
   if(g_state.beApplied)
      baseSL = ProtectiveSL(baseSL, BEStopPrice(), dir);
```

**After:** hoist ONE boundary read above the baseline, then add the third fallback.

```
   // D19: ONE boundary read per pass, shared by the D17 baseline and the D16-C gate below.
   int    ddLvC  = 0;
   bool   ddNowC = false;
   double ddTrC  = 0.0;
   double ddBC   = InpEnableDDClose ? DDBoundaryPrice(ddLvC, ddNowC, ddTrC) : 0.0;

   double baseTP = (g_state.manualTP > 0.0) ? g_state.manualTP : compTP;
   double baseSL = (g_state.manualSL > 0.0) ? g_state.manualSL : compSL;
   // *** D17 (E9-R2-C): THE THIRD FALLBACK. ***
   bool   baseSLisBoundary = false;
   if(baseSL <= 0.0 && ddBC > 0.0)
     { baseSL = ddBC; baseSLisBoundary = true; }
   if(g_state.beApplied)
      baseSL = ProtectiveSL(baseSL, BEStopPrice(), dir);
```

- **Ordering is safe, and the reason is NARROWER than it first looks.** The window `:1886`–`:1961`
  is NOT mutation-free — `:1936` writes `g_state.manualTP`. The hoist is safe because
  `DDBoundaryPrice`’s body reads **only** `g_state.direction`, `g_state.levelCount` and
  `g_state.tickets` (**scanned, `:4244`–`:4322`**), none of which that write touches. Recorded
  precisely so a later build that makes the boundary read more state knows this is load-bearing.
- **A-5 is enforced by the `InpEnableDDClose ?` guard**, not by a later test. Cap off → `ddBC` is
  0.0 → `baseSL` stays 0.0 → nothing classified → the C-11/D16-E orphan case is untouched.
- **A-6**: no tick value → `DDBoundaryPrice` returns 0.0 → same fallthrough, no crash.
- `baseSLisBoundary` is the flag D18 needs. It is NOT persisted — pass-local only (**D-2**).
- `baseTP` is deliberately untouched: the TP path was never broken.

**After:** a three-way, because under D17 the first arm is unreachable (matrix **C-1**):

```

                                       DoubleToString(candSL, _Digits),
```

the points figure is measured against the floor, not the raw boundary. The message says
"boundary", which would then be imprecise. **Resolution:** set `baseSLisBoundary = false` inside
the `beApplied` branch when `ProtectiveSL` actually returns the floor. One extra line, and it
keeps **C-3** honest.

## RISK, STATED PLAINLY

The whole change is **one new fallback, one hoist, one new log branch, one deletion, one comment
block**. The sharp edge is not the fallback — it is that `baseSL` now means something different
downstream, and **four branches were written assuming it was a computed SL**. TP3 handles the one
that becomes unreachable; the BE interaction is handled by the `baseSLisBoundary = false` line.
**The thing most likely to be wrong is the BE composition**, because it is the only place where
two baselines can both be non-zero. Matrix **C-3** is the row that catches it.

## BUILD ORDER

Single stage, one Gate Zero at the end. The change is small enough that splitting it would add
more risk (two final-byte trims) than it removes — b52's two-stage build is what produced the
`--+` trim error.
